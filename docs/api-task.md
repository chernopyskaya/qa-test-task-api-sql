# 🔌 Задание 1. Тестирование API: метод «Создание организации»

## 🎯 Задача

Составить коллекцию Postman для полного тестирования метода `POST /api/v1/de/organization`.

Условия:

- 🔑 коллекция запускается без дополнительных действий, нужно только подставить свой токен авторизации;
- 🚫 вкладки Scripts, Tests и переменные окружения не используются;
- 📖 каждый запрос понятен по названию, параметрам, заголовкам, телу и ответу.

## 🧭 Подход

1. 📚 Разобрала описание метода: обязательность полей, ограничения по длине и формату, алгоритм работы.
2. ✅ Собрала один рабочий запрос и проверила, что он возвращает `200` и `id` организации.
3. 🔁 Остальные кейсы сделала копиями рабочего запроса. В каждом кейсе меняется **одно** значение, чтобы было понятно, что вызвало результат.
4. 🗂️ Разложила кейсы по папкам. В каждой папке сначала идут позитивные кейсы, потом негативные.

## 🧰 Применённые техники

- 🧩 **Классы эквивалентности:** допустимые и недопустимые значения для каждого поля.
- 📏 **Граничные значения:** для диапазона 2–100 символов проверены значения 1, 2, 3, 99, 100, 101. Аналогично для `address` (5–255) и для имени, фамилии и отчества руководителя (2–60).
- ❓ **Проверка обязательности:** поле не передано, пустая строка.
- 🔢 **Проверка формата:** ИНН (10 или 12 цифр), ОГРН (13 цифр), телефон (`+7`, `7` или `8` и 10 цифр).
- 🔤 **Проверка типов данных:** число вместо строки.
- ⚙️ **Проверка логики метода:** повторный ИНН, обязательность ОГРН при ИНН из 10 цифр, необязательность ОГРН при ИНН из 12 цифр.

## 🗂️ Структура коллекции

| Папка | Что проверяется |
|---|---|
| ✅ 00 Основной сценарий | успешное создание организации |
| 🏢 01 name | длина 2–100, обязательность, тип |
| 🔢 02 inn | длина 10 или 12 цифр, обязательность, тип |
| 🧾 03 ogrn | 13 цифр, обязательность при ИНН из 10 цифр |
| 📍 04 address | длина 5–255, обязательность |
| 📞 05 phone | допустимые префиксы и длина |
| 👤 06 head | массив руководителей, обязательность |
| 🙂 07 head.firstName | длина 2–60, обязательность |
| 🙂 08 head.lastName | длина 2–60, обязательность |
| 🙂 09 head.middleName | необязательное поле, длина 2–60 |
| 🔐 10 Авторизация | нет токена, неверный токен, пустой токен |
| ♻️ 11 Дубликаты | повторное создание с тем же ИНН |
| 📦 12 Тело запроса и метод | пустое тело, пустой объект, невалидный JSON, неподдерживаемый метод |

Название каждого запроса показывает, что проверяется и какой результат ожидается, например `name: 101 символ → 400`.

## 💡 Особенности

- 🕒 ИНН в большинстве кейсов формируется автоматически (`{{$timestamp}}` и номер кейса), поэтому повторный запуск не вызывает ошибку «Организация уже зарегистрирована».
- ♻️ В папке «11 Дубликаты» используется фиксированный ИНН: сначала выполняется подготовительный запрос, потом запрос-дубликат. При повторном запуске подготовительный запрос вернёт `400`, это нормально.
- 🔐 Кейсы папки «10 Авторизация» не используют токен коллекции, потому что проверяют именно неверный или отсутствующий токен.
